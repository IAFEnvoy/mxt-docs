# `/lifespan`

`/lifespan`（= `/mxt lifespan`）读写每个身体的**寿元账本**：还剩多少刻与这一世被给到的上限。账本从哪里来、怎么结算、耗尽后发生什么，见[寿元](/player-guide/lifespan)。

| 命令 | 作用 |
| --- | --- |
| `/mxt lifespan` / `/mxt lifespan get`（= `/lifespan`、`/lifespan get`） | 读执行者自己的账本。 |
| `/mxt lifespan get <targets>` | 打印每个目标的账本（需要 gamemaster 权限）；从没记过账的目标报「未记账」。 |
| `/mxt lifespan set <targets> <ticks>` | 把剩余与上限一起改写成 `ticks`（需要 gamemaster 权限）；`ticks` 不得为负。 |
| `/mxt lifespan add <targets> <ticks>` | 增减寿元（需要 gamemaster 权限）：正数同时抬高剩余与上限，**负数只扣剩余、不动上限**。 |
| `/mxt lifespan reincarnate <targets>` | 让每个目标当场**转世**（需要 gamemaster 权限）：跑一遍服务端配置「转世」页那份重置清单，再把账本按服务端配置「寿元 → 凡人基础寿元」重开。 |

## 说明

- 读出的是刻，按服务端配置「寿元 → 每岁刻数」换算成「岁」显示（填 `1` 就直接显示刻）。
- 「未记账」与「耗尽」是两回事：前者是身体从没有过账本（公式变量此时读作 `NaN`），后者是账本停在 `0`。`get` 只在从没有账本时说「未记账」；`set` 与 `add` 都能给前者开账、给后者续命。
- 目标必须是生物实体：不是生物时那一行会点名它并跳过，其余目标照旧处理。
- 写入**不受寿元总开关影响**：开关只管时间流不流逝，命令照记账。
- `reincarnate` 跑的就是耗尽后果选 `reincarnate` 时的那份重置清单（转世标签页上的那些开关），跑完按服务端配置「寿元 → 凡人基础寿元」重开账本：那个值是 `0`（默认）时就等于关闭账本，身体重新读作「未记账」。
- 清单里的服务端配置「转世 → 转世先死一次」开着时，身体会**先真的死一次**（走正常的伤害与死亡流程：掉落物品、死亡消息、重生点），然后才跑重置清单。
- 转世**不发 `lifespanEnd` 事件**——那个事件只属于寿元耗尽——它发的是 `lifespanRebirth` 的 `Pre` / `Post`，所以监听者可以拦下它（细节见 [MxtEvents](/kubejs/api/events)）：`Pre` 被取消时，**这个目标报成一次失败**，失败行用的是「被监听者拦下」，而不是一行成功；**其余目标照旧处理**。
- 与 `set` / `add` 一样，`reincarnate` **不受寿元总开关影响**：这是当场落下的裁决，不是时间流逝，开关关着也照做。
- 目标如果是玩家，**本人会在聊天栏收到一句通知**（"你被重铸为凡人之身，此前的道基与修为已尽"）：命令的反馈只发给执行者，而一身修为当场没了的人不该一无所知。

顶层别名 `/lifespan` 由服务端配置「命令别名 → /lifespan」控制（默认开启）；关闭后 `/mxt lifespan` 照旧可用。
