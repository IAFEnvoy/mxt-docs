# `/physique`

体质的管理入口。定义本身是数据包，授予、移除和开关则是实体身上的状态：这一页是操作这三件事的地方，也是「关闭但不失去」那个模块在体质一侧的管理员侧入口（模块没有玩家界面）。

| 命令 | 作用 |
| --- | --- |
| `/physique list [<目标>]`（= `/mxt physique list`） | 列出持有的体质：名字、稀有度与是否生效（叠加时同名只列一行）。不填目标时看自己，查询不需要权限。 |
| `/physique grant <目标s> <体质>` | 授予体质（gamemaster）。持有条件 `holder_condition` 不满足、与已持有体质的互斥标签相冲或定义不存在时，逐个目标报出原因。 |
| `/physique remove <目标s> <体质>` | 移除该体质，连同它给的属性与一切授予。 |
| `/physique enable` / `disable <目标s> <体质>` | 与灵根同义的开关：关闭后属性修正、授予能力与两个伤害倍率全部不生效，但体质仍然被持有。 |

授予与移除走的是数据包行为 `mxt:grant_physique` / `mxt:remove_physique` 等**同一套服务**，所以持有条件、互斥标签与来源清理完全一致，命令不会绕过任何一条校验。失败按目标逐个报告，原因写在后面。

`<体质>` 的补全只列出仍在加载的定义。一个身体仍然持有、而定义被 **`mxt:disabled` 停用**的条目可以手打 ID 来移除或关闭：`remove` / `enable` / `disable` 都按身体持有的那条引用来找、不回查注册表，所以停用不会把它们挡住。**已经删除**的定义则到不了这里——附件里存的是定义本身，解码时那条会被丢掉。

体质没有绑定元素，所以列表里就没有元素那一栏。

顶层别名 `/physique` 由服务端配置的**「命令别名」标签页**控制（条目名 `physique`，默认开启）；关闭后 `/mxt physique` 照旧可用。
