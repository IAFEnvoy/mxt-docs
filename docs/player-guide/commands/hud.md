# `/hud`

| 命令 | 作用 |
| --- | --- |
| `/hud` | 列出框架登记的全部可移动 HUD 元素：布局键、显示名、位置、尺寸、当前要画几个块、是否可见、是否可拖。 |
| `/hud open` | 打开 HUD 布局编辑器，等同于按键 `key.mxt.hud_layout`（默认右 `Shift`）。 |
| `/hud <布局键> reset` | 把某个元素复位到它自己的默认位置，布局键见 `/hud` 的输出（如 `resource_bars.left`）。复位会**同时删掉这个元素已保存的那一项**，所以它跨重启有效；删掉之后这个元素重新跟着窗口走（默认位置就定义在窗口上），直到你再次拖动它。 |

`/hud` 是**客户端命令**：它注册在客户端自己的命令表里，不进 `/mxt` 树、也不发往服务端，所以只在聊天栏里手打有效（写进命令方块、或由别的模组代为发送都不行），不需要任何权限。这条命令与按键 `key.mxt.hud_layout` 打开的是同一个编辑器。

## 它为什么存在

「编辑器里一个元素都没有」和「元素登记了、只是这一帧没有内容」在界面上长得一模一样，只有这条命令能把两种情况分开：

- 打出 `HUD 布局里没有任何可移动元素`＝框架里根本没有登记过元素；
- 打出 `resource_bars.left` / `resource_bars.right` / `wheel.selection` 这几行、而「绘制块」是 `0`＝框架有元素，只是现在没有内容可画——没有资源条的存档里那两列仍然是空框（尺寸还是空列的 71×8），「轮盘格」整块自绘，所以永远是 `0` 块、尺寸随内容变。

顺带一提，`/hud` 打出的位置与尺寸就是元素**此刻**在窗口里的矩形：位置按窗口比例保存，换分辨率或改 GUI 缩放之后布局不会跑偏，元素也始终被夹在窗口内。

拖动、复位与各元素的默认位置见[轮盘、资源条与灵气 HUD](../keys-and-hud.md#hud-布局编辑器)；框架侧怎么登记一个元素见[客户端界面](../../java/screens.md)。
