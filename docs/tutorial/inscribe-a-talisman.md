# 符箓：从定义到发动

符箓是把技能装在物品上：一张符箓铭刻若干能力，灌满它的灵气账单，它就把这些能力替你放出去。**定义只写「铭刻了什么、要付多少」**；至于「灌满就自动放」还是「存着等你动手」，是**载体自己（物品堆上）的模式**，不是定义的属性。

::: warning 铭刻还没有游戏内入口

符笔 `mxt:talisman_brush`、符墨 `mxt:talisman_ink`、空白符纸 `mxt:blank_talisman` 目前都是**没有行为的普通物品**——"拿着符笔右键把技能刻上去"这条路还没接。今天能把符箓写进载体的只有三处：`/talisman give …`、物品组件语法（`/give` 的 `components`）、创造模式检索里生成的单条铭刻物品。

所以这一篇讲的是**定义 → 发放 → 灌注 → 发动**这条现在真的能跑完的链；等铭刻服务落地，第 3 步会补上手工那条路。

:::

## 你要搭建什么

| 文件 | 用途 |
| --- | --- |
| `data/example/mxt/aura/qi.json` | *（已有）* 符箓的账单只能引用**具体**的灵气定义。 |
| `data/example/mxt/ability/spark.json` | 要被铭刻的技能。 |
| `data/example/mxt/talisman/flame_sigil.json` | 符箓定义：铭刻哪些技能、要付多少灵气。 |

## 第 1 步 —— 一个能被承载的技能

```json
// data/example/mxt/ability/spark.json
{
  "ability": {"type": "mxt:active", "slot": "primary"},
  "cooldown": 60,
  "entity_action": {
    "type": "mxt:apply_effect",
    "effect": "minecraft:fire_resistance",
    "duration_ticks": 120
  }
}
```

**只有立即生效的能力能被符箓承载。**需要吟唱（`cast_time > 0`）或持续引导（`mxt:channelled`）的能力会被拒绝，因为唱法与引导的收尾靠"持有者已授予的能力"列表推进，而载体从不授予任何东西。被拒绝时载体不消耗、灵气也不清空，可以换一张符或换一个能力。

## 第 2 步 —— 符箓定义

```json
// data/example/mxt/talisman/flame_sigil.json
{
  "abilities": ["example:spark"],
  "aura_cost": {"example:qi": 12}
}
```

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `abilities` | `HolderOrTag<ability>[]` | `[]` | 铭刻的能力：单个 ID、ID 数组或 `#标签`，写法与 `technique.granted_abilities` 一致。 |
| `aura_cost` | `Map<Holder<aura>, NumberProvider>` | `{}` | 激发账单，**同时也是载体的容量**；按具体 aura 分键，值可写常量或公式。 |

三条要记住的语义：

- **`aura_cost` 只收具体 ID，不收 `#标签`**：灵气池本来就按具体 aura 分池，标签在这里找不到对应的池子。
- **账单按空公式上下文求值**：客户端要为姿势算出同一个数，所以能不能写取决于"脱开持有者也成立"。`"realm_rank * 4"` 这类只在有人时才有值的写法会求出 `0`，被当作**这条不参与灌注**；一条都不剩的载体等同于免费符。
- **账单即容量，没有独立的容量字段**：把账单灌满，符就算"满了"，那一刻发动并消耗一件载体（一用即焚）。

## 第 3 步 —— 把符箓交到玩家手里

```text
/talisman blank                                 给一张空白载体
/talisman give example:flame_sigil              给一张铭刻好、未灌注的载体
/talisman give example:flame_sigil count 3      给三张
/talisman give example:flame_sigil charged      给一张并直接灌满——下次点按即发动
/talisman give example:flame_sigil stored       以 store 模式铭刻（只积累，等你动手）
```

整棵 `/talisman` 子树需要 gamemaster 权限；顶层别名 `/talisman` 受服务端配置「命令别名 → /talisman」控制（默认开启），关掉之后 `/mxt talisman` 仍然完整。`charged` 与 `stored` 不能组合，且 `charged` 只能写在 `count` 之后。

不想用命令时，直接写物品组件也行——载体上存的是**具体条目列表加一个模式**：

```mcfunction
give @s mxt:talisman[mxt:talisman={talismans:["example:flame_sigil"],mode:"fire"}]
```

`mode` 缺省就是 `"fire"`；空列表等于刚做出来的空白载体。灌注进度另存在 `mxt:spirit_storage`（与灵石共用同一个存储组件）。

## 第 4 步 —— 灌注与发动

**灌注**：主手持有载体，**按住右键不放**（与灵石灌注同一套手势：`BLOCK` 姿势、每 4 tick 一次提示音、action bar 显示「已存 / 容量」）。每 tick 灌 1 单位、1 单位收 1 点自身灵气，所以 `12` 的账单要按满 12 tick；一次手势最多 200 tick。**灌注期间不消耗物品**，只有发动时才消耗一件；灵气则是在灌注时就按 1:1 扣掉的。

**发动**由载体模式决定：

| 模式 | 行为 |
| --- | --- |
| `fire`（默认） | 灌满那一刻**自动发动**。 |
| `store` | 只积累，不自动发动；**右键**才发动。 |

**潜行 + 右键**切换模式（会有一句 action bar 提示，tooltip 里也写着当前模式）。一条特例：`store` 且**已经灌满**时，潜行使用**不切换**——它直接发动并消耗那张符（存着的灵气就是拿来花的）。

发动时铭刻的能力**逐个走普通的能力使用流程**：能力自己的条件、冷却、次数与消耗全部照旧，唯一被替换掉的是「该能力已授予你」这一条——**符箓自己就是授权的来源**。所以带一张符就能放你不会的法术，但符箓**不是绕过这些门的后门**。只有**至少一道能力真的发动成功**才消耗载体并清空它的灵气；全部被拒时载体和灵气都还在。

**手持发动有冷却**，由服务端配置「符箓 → 使用冷却」控制（单位 tick，范围 `0..72000`，默认 `20`）——不在数据包里。它的边界值得记清：

- **一次「尝试」就进冷却**：能力因为自己的冷却或消耗付不起而被拒，也算尝试（那次点击确实是发动）。
- **空载体、没灌满这两种点击不算尝试**，不花冷却——它们本来只是给玩家一句说明，立刻就能改。
- 因为模组的载体都是同一个物品 `mxt:talisman`，这份冷却是**按玩家、按物品**记的：手上另外几张符在窗口内也一起按不动。

## 第 5 步 —— 展示架：不在手上也能发动

把载体放进展示架（手持右键方块放入，**放入不发动**），再用灵力射线（默认 `V`）对准它灌注——灌满那一刻它就地发动。

展示架那条路和手持是**两套规则**：

| | 手持 | 展示架 |
| --- | --- | --- |
| 使用冷却 | 读，也记 | **完全不看**，也不记 |
| 消耗载体 | 消耗一件，**创造模式不消耗** | **永远消耗**，与填料的人是不是创造模式无关 |
| 行为者 | 持有者 | **填料的人**（出账、被记录、为其能力作答） |
| 位置 | 行为者自己 | **展示架中心** |

位置以 `block_x`/`block_y`/`block_z` 进入公式上下文，并作为这次激发的**原点**交给位置类行为（`spawn_projectile`、`spawn_particles`、`explode`、`mxt:area` 的圆心……）；投射物仍按**行为者**的朝向发射——位置是"从哪里发出"，朝向是"谁在瞄"。架上灵气**取不回来**（展示架的取出是空操作），要拿回物品就空手右键或破坏方块。

## 在游戏里验证

数据包注册表在**世界加载时**读取，所以先退回标题界面重开世界，然后：

```text
/mxt registries validate
/talisman give example:flame_sigil charged
```

1. `validate` 无 Codec 错误。
2. 手上出现一张「符箓」：tooltip 显示当前模式与「已铭刻符箓」，`charged` 给的那张还写着「灵气已满，右键激发」。
3. 右键发动：一道 `example:spark` 被放出去（获得 120 tick 抗火），载体消耗一件，灵气的存储组件被清空。
4. 再要一张不加 `charged` 的，**按住右键**灌注：action bar 显示已存 / 容量，每 4 tick 一声提示音，12 tick 后灌满自动发动。
5. 试 `stored`：灌满只提示「已存储」，随后右键才发动；潜行右键能在两种模式之间切换。
6. 试冷却：连点两张符，第二张会提示「符箓尚在冷却」，窗口内长按也不会把灵气灌进去。
7. 试展示架：放一个展示架、把符放进去（不发动），用 `V` 瞄准它灌注——灌满即就地发动。

## 常见错误

| 现象 | 原因 |
| --- | --- |
| 右键只提示「未铭刻任何道法」 | 载体是空的（`/talisman blank` 给的就是这种）；这种点击不算一次尝试，也不进冷却。 |
| 右键提示「灵气尚未充满」 | 账单没灌满；先按住右键灌注，或用 `/talisman give … charged`。 |
| 提示「该道法已被禁用」 | 能力被 `mxt:disabled` 停用了；符箓不绕过停用。 |
| 提示「灵根与该道法属性不合」 | 能力的 `element_affinity` 与施法者灵根不匹配——符箓也不绕过它。 |
| 提示「需要吟唱或持续引导，符箓无法承载」 | `cast_time > 0` 或 `mxt:channelled` 的能力不能被承载。 |
| 灌不满 / 按了没反应 | 账单里有条目在空上下文里算出了 `0`（例如用了 `realm_rank`），它不参与灌注；或者手上灵气不够（会提示「灵气不足」）。 |
| 组件写法被拒绝 | `aura_cost` 与 `talismans` 都只收具体 ID；写 `#标签` 只有 `abilities` 允许。 |
| 发动成功但灵气还在 | 灵气组件在成功那一刻被整体移除，**一叠符里剩下的那几张是空的**，不会继承这次灌注。 |
